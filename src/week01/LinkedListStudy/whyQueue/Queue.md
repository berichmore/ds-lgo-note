## 📘 Chapter 1. Queue란 무엇인가? - 철학과 개념  

### ✅ 1-1. Queue의 본질 - "선입선출(FIFO)"의 철학  

> Queue의 정의:  
> "먼저 들어온 데이터가 먼저 나가는 구조 (First In, First Out)"를 따르는 선형 자료구조  
>

### 🎯 예시로 바로 이해해보자:  
- 식당에서 줄 서는 모습  
  - 먼저 온 손님이 먼저 주문하고 나간다.  
- 콜센터 대기 전화  
  - 먼저 건 전화가 먼저 상담원에게 연결된다. 
- 프린터 인쇄 대기열  
  - 먼저 보낸 문서가 먼저 출력된다.  
> 이 구조를 관통하는 철학은 "질서"와 "공정함"이야.  

### ✅  1-2. Stack vs Queue 비교 - 왜 서로 다른가?  
> 항목 | Stack      | Queue  
> --|------------|--|
> 규칙 | LIFO(후입선출) | FIFO(선입선출)|
> 사용 사례 | 되돌리기, 함수 호출 | 줄 서기, 작업 대기 |  
> 입출 방향 | 한쪽(Top)에서 push/pop| 앞(front)에서 제거, 뒤(rear)에서 삽입|  
> 주요 연산 | push(),pop(),peek()| offer(),poll(),peek()|

- Stack은 "시간을 되돌리기 위한 구조"  
- Queue는 "시간 순서로 보장하기 위한 구조"  
즉, Stack이 과거로 가는 구조라면,  
- Queue는 미래를 향해 나아가는 구조라고 볼 수 있어.  

✅ 1-3. Queue의 인간적 직관 - 줄을 선다는 것의 의미  
> "한 명씩 차례대로"라는 말은 컴퓨터가 아니라 사람이 만든 규칙이야.  
> 
> - 컴퓨터는 본질적으로 순서에 관심이 없어.  
> - 하지만 사람은 공정함과 처리 순서에 매우 민감하지.  
> 그래서 Queue는 다음과 같은 인간의 필요에서 탄생했어:  
> - "먼저 온 요청부터 처리해줘. "  
> - "한꺼번에 처리 못하니 순서를 정해서 기다려줘."  
> - "지연되더라도 내가 낸 순서대로 처리하면 괜찮아"


✅ 1-4. Queue는 어디에나 있다 - 세상을 관통하는 큐 구조  

💡 실생활 예시  
- 🚦교차로 신호 대기 (차량이 순서대로 지나감)  
- 🛒마트 계산대 (앞사람이 끝나야 내가 계산 가능)  
- 🎮 게임 서버 대기열 (먼저 접속한 유저가 먼저 입장)  
- 📦 택배 물료창고(먼저 입고된 순으로 배송 처리)  

💻 컴퓨터 시스템 예시  
- 🧠 CPU 프로세스 스케줄링(ready queue)  
- 📧 메일 전송 대기 (SMTP 큐)  
- 🔔 이벤트 큐 (사용자 클릭, 시스템 인터럽트 처리 순서)
- 🎞️ 버퍼링 (재생 순서대로 데이터 받아옴)  

✅ 1-5. 왜 Stack이 아닌 Queue인가?  
> 상황| 왜 Stack이 안 되는가? | Queue가 필요한 이유  
> --|--|--|
> 프린터 인쇄 대기| 마지막 요청이 먼저 처리되면 사용자 불만| 먼저 요청한 작업 순서 보장|
> 콜센터 전화| 마지막 고객이 먼저 받으면 불공정| 먼저 건 전화 순서 보장|  
> CPU 작업 처리 | 최근 작업만 처리하면 나머지 무한 대기| 전체 작업 순환 보장|
>  -> 시간 순서를 보장하고 모든 요청을 순차적으로 처리하기 위해 Queue가 필요했던 것.  
>

✅ 1-6. Queue는 단순한 배열이 아니다 - 추상적 개념의 힘
- 많은 초보자가 "배열 쓰면 되잖아?"라고 생각해.  
- 하지만 배열은 단순히 값을 담는 도구이고,  
- Queue는 **행동 규칙**이야.  
- 즉, 큐는 **추상 자료형(Abstract Data Type)**이야.  
> ❗"데이터를 어떻게 저장하느냐"보다 중요한 건  
> ❗"데이터를 어떤 순서로, 어떤 규칙으로 다루느냐"야.  

✅ 1-7. Queue의 3대 핵심 연산  
>연산 이름| 의미 | 자바 메서드 예시 |  
> --|--|--|  
> Enqueue | 데이터 삽입 | offer() 또는 add() |
> Dequeue| 데이터 제거 | poll() 또는 remove()|
> Peek | 맨 앞 확인 (삭제 없음)| peek() 또는 element()|  

✅ 1-8. Queue의 기본 작동 순서 시각화  
```less
초기 상태: [ ]  (비어 있음)  

offer(10) -> [10]  
offer(20) -> [10, 20]  
offer(30) -> [10, 20, 30]  

poll() -> 10 반환,  [20, 30]  
poll() -> 20 반환, [30]   
```  
이처럼 앞(front)에서 꺼내고, 뒤(rear)에서 넣는 구조.  
-> 이 원칙이 깨지면 큐가 아님!  
 
✅ 1-9 Queue는 "시간을 흐르게 만드는 구조"  
- Stack은 과거로 회귀하게 만드는 구조  
- Queue는 미래로 이동하게 만드는 구조
> 그래서 Queue는 "시간이 흐르는 시스템"에 가장 적합한 자료구조야.  
>

✅ 1-10. Chapter 1 핵심 요약  
> 항목 | 설명  
> --|--|  
> 철학 | 선입선출(FIFO), 질서, 공정함|  
> 목적 | 순차 처리, 시간 순서 유지  |  
> 실제 사용처 | 프린터, 콜센터, CPU 스케쥴링, 게임 서버 등|  
> 연산 | offer(), poll(), peek()|  
> 핵심 구조 | front에서 제거, rear에서 삽입 |

## 📘 Chapter 2. Queue는 왜 등장했는가 - 필요의 역사  

### ✅ 2-1. 자료구조의 탄생은 '문제를 해결하기 위한 도구'였다.  
Queue도 처음부터 "이런 멋진 구조를 만들자!"는 이상에서 출발한게 아니야,  
현실의 복잡한 문제들을 해결해야 했고,  
그 문제에 가장 잘 맞는 구조가 "Queue(선입선출 구조)"였던 것 뿐이야.  
> Queue는 결국 "현실의 순차 처리 문제"를 해결하기 위한 결과물이야  
>

### ✅ 2-2. CPU와 운영체제의 대기열 문제  

🔧 문제 상황 :  
- 컴퓨터는 한 번에 하나의 일만 처리 가능(단일 CPU 기준)  
- 하지만 사용자들은 동시에 여러 작업을 요청함  


👀 예시 :  
- A는 워드프로세서 실행  
- B는 유튜브 실행  
- C는 백신 검사 요청
> 만약 선입선출 구조가 없다면 어떤 일이 벌어질까?  
- C처럼 가장 나중에 요청한 작업이 실행된다면?  
- A, B 사용자는 끝없이 대기 -> 시스템에 대한 불만 -> 비효율  

💡 해결책 : Ready Queue(준비 큐)  
- 운영체제는 **모든 작업 요청을 순서대로 대기열에 넣고,  
  CPU는 그 큐에서 하나씩 꺼내 작업을 처리 **  
> -> 바로 이 때 등장한 것이 Queue 자료구조였어  

--- 
### ✅ 2-3. 프린터 인쇄 문제 - 비순차 

🖨️ 문제상황 :  
- 여러 명이 네트워크 프린터에 출력 요청을 보냄  
- 어떤 요청이 먼저 도착했는지를 무시하면?  
🧨발생 가능한 문제:  
- 먼저 요청한 문서가 뒤로 밀림  
- 짜증, 혼란, 문서 누락  

💡해결책 : Print Queue(인쇄 대기열)  
- 프린터는 도착한 순서대로 문서를 출력  
- 즉, "먼저 도착한 요청부터 먼저 처리"  
> 이 시스템을 유지하기 위한 핵심 구조 = Queue

### ✅ 2-4. 병우너 접수 시스템, 은행 창구 - 사람 세상의 문제도 같다.  
> 현실의 줄서기 문제는 **컴퓨터 시스템에 그대로 반영됨**  

🏥 병원 접수  
- 먼저 온 환자가 먼저 진료를 봐야 공정하다
💰 은행 창구  
- 먼저 온 사람이 계속 뒤로 밀리면 불만 유발  
> 이처럼 사람이 만든 질서를 유지하기 위해서도 Queue가 필수적이야  

--- 
✅ 2-5. 네트워크 데이터 전송 - 패킷 순서 문제   
🌐 문제 상황:  
- 인터넷은 데이터를 작게 쪼개서 보냄 (패킷 단위)  
- 서버에 동시에 수많은 요청이 도착
📦 전송 시 고려해야 하는 조건:  
- 누가 먼저 보냈는가?  
- 전송 순서가 어긋나면 재조립 불가  
💡 해결책:  
- 데이터 요청은 Queue에 순서대로 저장  
- 서버는 Queue에서 순서대로 응답 처리  
> -> 여기서도 Queue는 순서 보존과 병목 해소의 도구로 사용됨  

✅ 2-6. 키보드 입력 처리 - 입력은 순서대로  
⌨️ 문제상황:  
- 사용자가 A, B, C를 순서대로 입력했는데  
  컴퓨터가 C, B, A를 순서로 처리하면? 
> 👉 게임에서 기술이 꼬이고, 문장 순서가 뒤바뀌는 혼란    

💡 해결책 : Input Queue(입력 큐)  
- OS는 키보드 입력을 Queue에 저장하고,  
  입력된 순서 그대로 처리  

✅ 2-7. 실시간 처리와 이벤트 핸들링 - '순서'는 생명이다.  
🎮 게임에서의 이벤트 처리  
- 적이 총을 쏘고 -> 프레이어가 점프하고 -> 동전이 떨어지는 순서  
📱 앱에서의 UI 입력 처리  
- 사용자가 버튼 클릭 -> 알림 뜸 -> 백그라운드 음악 정지  

모든 이벤트는 순서를 따라야만 의미가 있다.  
> -> **이 순서를 지키기 위한 큐(Event Queue)**가 항상 존재한다.

✅ 2-8. 인간이 만든 순서를 컴퓨터가 따르게 만드는 유일한 도구  
❓ 왜 Stack이나 배열은 이 문제를 해결할 수 없었는가?  
> 구조 | 한계 |  
> --|--|  
> Stack | 최근 것만 먼저 처리 -> 공정성 붕괴|  
> 배열 | 삽입/삭제 위치가 유연하지 않음 -> 비효율 |  
> Queue| 삽입/삭제 위치 고정 + 순서 보장 -> 최적 구조 |  
---  
### ✅ 2-9 Queue는 컴퓨터의 시간성을 보장하는 구조  
- Queue는 단순한 리스트가 아니라,   
  **시간을 기록하는 선형적인 흐름**  
> 즉, "컴퓨터가 '과거 -> 현재 -> 미래'의 순서를 따르게 만드는 기초구조"야
