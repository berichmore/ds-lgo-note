# 시간복잡도란..?

지금부터 시간복잡도(Time Complexity)에 대해 3만자 이상 분량으로 아주 상세하게 설명할게.  
단순히 외우는 게 아니라, 진짜로 이해하고, 내 것으로 만들 수 잇도록  
> 원리 -> 수학적 기초 -> Big-O 표기법 -> 실전 예시 -> 잘못된 직관 -> 면접까지 연결
> 
> 모든 내용을 스토리로 구성

### 🧠 1. 왜 시간복잡도가 중요한가?  

개발자들이 처음 알고리즘을 짤 때 흔히 착각하는 게 있어.  
> "코드가 돌아가면 끝 아니야?"  
> 하지만 실제로는 다음과 같은 질문이 따라 붙는다.  
> - 코드가 빨라야 하는 이유는?  
> - 이게 100만개의 데이터를 받을 때도 작동할 수 있을까?  
> - 서버에서 이 코드가 1초 안에 끝날 수 있을까? 
> 
> 
> 이때 등장하는 것이   
> "**코드가 얼마나 빨리 실행되는지를 입력값 크기(n)에 따라 정량적으로 표현**" 한거야  
> 성능을 정량적으로 비교할 수 있는 유일한 방법이지.  

### 🔢 2.시간 복잡도의 개념과 정의  

📘 개념 요약  
시간 복잡도는, 
> "입력 크기 n에 따라, 연산 횟수가 어떤 패턴으로 증가하는가?"를 나타내는 수학적 표기법이다.  
> 예를 들어:  
> 
>| n(입력 크기) | 연산 횟수|  
> |---|---|
> | 1 | 1|
> |10 | 10|
> |1000| 1000|
> -> 이런 패턴이면 시간복잡도는 O(n)이다.  
> 즉, n개의 데이터를 처리하면 n번 연산한다는 뜻이지.  

📗 예제 코드 1 - O(n)  
```java
for(int i = 0; i < n; i++){
    System.out.println(i);
        }
```
-> 입력값이 n일 때, 반복 횟수도 n이다.  
-> 이걸 0(n)이라고 한다. 선형 시간복잡도. 

🔍 3. Big-O 표기법의 원리  
📘 왜 'O'를 붙일까?  
O는 "Order of"의 약자야.  
즉, "어느 정도 크기 수준인가"를 나타내는 수학 기호지.  
- O(1) -> "1차례ㅖ(상수 수준)의 연산"  
- O(n) -> "입력 n에 비례한 연산"  
- 0(n^2) -> "입력의 제곱만큼 연산" (예: 이중 for문)

Big-O는 "상한선(최악의 경우)"을 기준으로 작성한다는 점이 중요해.  
(평균, 최선도 있지만, 일반적으로 O(n)은 최악 기준이야. )  

🧱 4. 다양한 시간복잡도 사례  
✅ O(1) - 상수 시간  
- 데이터가 몇 개든 관계없이 연산이 항상 1번  
- 예: 배열에서 인덱스로 값 가져오기  
```java
int val = arr[0]; // 0(1)
```

✅ O(n) - 선형 시간  
- 데이터 수(n)에 비례해서 연산 횟수가 늘어남  
- 예: 배열 순회
```java
for(int i = 0; i < n; i++){
    sum += arr[i];
        }
```

✅ O(n^2) - 이중 루프  
- 입력이 10이면 100번 반복 (10 * 10)  
- 예: 버블정렬, 브루트포스 이중 비교  
```java
for(int i = 0; i < n; i++){
    for(int j = 0; j < n; j++){
        if(arr[i] == arr[j]) ...
        }
        }
```

✅O(log n) - 로그 시간
- 매번 절반씩 줄이는 알고리즘  
- 예: 이진 탐색
```java
while(low <= high){
    int mid = (low + high) /2;
    if( target == arr[mid]) return mid;
    else if (target <arr[mid]) high = mid -1;
    else low = mid + 1;
        }
```
✅ O(n log n) - 효율적인 정렬  
- 퀵정렬, 병합정렬의 평균 시간 복잡도  
- 실무에서 가장 많이 쓰이는 구조  

✅ O(2^m), O(n!) - 지수/팩토리얼 시간  
- 피보나치 재귀, 순열 생성 등  
- 입력이 조금만 커져도 연산이 기하급수적으로 폭증


🧠 5. 실전 계산 예시  
예제  1.O(1)  
```java
int a = arr[0];
```
-> 아무리 많은 데이터가 있어도 인덱스 접근은 한 번에 가능  

예제 2: O(n)  
```java
for(int i = 0; i < n; i++){
    System.out.println(arr[i]);
        }
``` 

-> 입력 크기만큼 반복 -> n번 반복

예제 3: O(n^2) 
```java
for(int i = 0; i < n; i++){
    for(int j = 0; j < n; j ++){
        System.out.println([i] + arr[j]);
        }
}
```
-> i당 j만큼 반복 -> n²번

📈 6. 시간복잡도 vs 실제 시간  

주의! 시간복잡도는 "실제 걸리는 시간"과 다르다.
> |요소 | 실제 실행 시간에 영향|
> |---|---|
> |CPU 성능 | 있음|
> |캐시 활용 여부 | 있음 |  
> |알고리즘 복잡도 | 큼 |  
> |입력 데이터 패턴  | 경우에 따라 다름  |
>
🔬 7.알고리즘 성능 비교 예시  
> |알고리즘 | 시간복잡도 | 설명    |  
> |--|--|-------|  
> |배열 검색 | O(n) | 순차탐색  | 
> |이진탐색| O(n^2)| 아주 느림|
> |퀵정렬 | O(n log n) | 평균적으로 가장 빠름|  
> |병합정렬| O(n log n ) | 안정 정렬(Stable Sort)|
>

💼 8. 면접 질문에서의 시간복잡도.  
자주 나오는 질문  
- 이 코드의 시간복잡도는?  
- 개선할 수 있다면 어떤 방식으로 바꿀 것인가?  
- 이중 for문을 없애고 효율적으로 만들 수 있는가?  
 -> 여기서 중요한 건 암기가 아니라,  
 **왜 이 알고리즘을 선택했는지를 논리적으로 설명할 수 있어야 한다는 점이다**


🔄 9. 시간 복잡도와 공간 복잡도  
공간복잡도란?  
- 메모리를 얼마나 쓰는가? 
- int[] arr = new int[n]; -> O(n)  

관계  
- 시간 줄이려면 공간 더 쓰고  
- 공간 줄이려면 시간 더 든다  

예:  
- 해시맵 -> 공간은 많이 쓰지만 탐색은 빠름(O(1))  
- 배열 정렬 후 탐색 -> 공간은 그대로지만 탐색은 log n  

📌 10. 시간 복잡도 분석 요령  
1. 중첩 반복문이 있는가? -> 곱하기 (O(n^2))  
2. 재귀 함수가 있는가? -> 재귀 트리의 깊이 고려  
3. 입력 크기 n은 어디에 있는가? -> 반복 조건에 주의  
4. 조건문은 시간 복잡도에 영향 없음 -> 연산 수 X

🧩 11. 잘못된 직관들  
- "for문이 하나면 항상 O(n)" -> 내부에 정렬 함수 있으면 다름  
- "재귀는 항상 느리다" -> 아닐 수도 있다 (이진탐색 재귀는 log n)  
- "시간복잡도가 낮으면 항상 빠르다" -> 실제 성능은 다를 수 있음  

🚀 12. 요약 정리  
>| 시간복잡도    | 의미    | 예시 코드 or 알고리즘 |  
>|----------|-------|---------------|  
>| O(1)     | 상수 시간 | 배열 접근, 해시탐색   |
>| O(log n) | 로그 시간 | 이진 탐색, 분할 정복 |
> |O(n^2) | 이중 반복문 | 버블정렬, 선택정렬|
> O(2^n), O(n!) | 기하급수적 증가 | 순열/조합 재귀, 백트래킹|

✅ 13. 마무리 : 진짜 실력을 만드는 건
